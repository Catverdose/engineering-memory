# 제품 요구사항과 범위

## 목적

개발자의 프로젝트 자료, 장애 기록, 기술 결정, 학습 노트를 쌓아 두고, 필요할 때 근거와 함께 다시 찾는 개인 지식베이스.

## 사용자

- 초기: 서버 관리자가 발급한 owner 계정. 회원가입 없음
- 데이터 경계는 처음부터 멀티유저를 전제로 설계함 (모든 데이터에 owner를 붙이고 조회마다 owner 조건 적용)

## 핵심 요구사항

| 영역 | 요구사항 |
|---|---|
| 등록 | 텍스트 붙여넣기, README·TXT·Markdown·LOG·PDF 파일 등록. 제목, 자료 유형, 프로젝트, 기술, 태그, 발생일, 원본 위치 메타데이터 |
| 색인 | 등록·수정 후 비동기로 청크·임베딩 생성. 상태(PENDING/READY/FAILED)를 화면에 표시. 재색인 가능 |
| 검색 | 프로젝트·기술·자료 유형·기간으로 범위 지정. 내 자료와 공용 기본 지식을 함께 검색 |
| 기본 지식 | 범용 기술 문서를 공용 자료로 제공. 첫 실행부터 기본 질문에 답할 근거가 있음 |
| 대화 | 멀티턴 대화, 스트리밍 답변, 답변마다 근거 문서와 원본 위치 표시 |
| 관리 | 문서 수정·삭제, 원본 다운로드, 대화 제목 변경·삭제 |

## 원칙

- 근거가 없으면 개인 경험인 것처럼 답하지 않음. 검색 결과가 없으면 모델을 부르지 않고 `NO_CONTEXT`로 안내함
- 다른 owner의 자료는 존재 여부도 드러내지 않음 (404)
- 개인 경험(Personal Knowledge)과 일반 기술 지식(Reference Knowledge)을 구분함. 일반 기술 지식은 owner 없는 공용 자료로 두어 모든 사용자가 읽고, 서버만 관리함. 답변할 때 공용 자료를 사용자 경험처럼 말하지 않도록 근거마다 구분해 모델에 전달함
- 계획 중인 기능을 이미 있는 기능처럼 안내하지 않음. 구현 현황은 [roadmap.md](roadmap.md) 기준

## 범위 밖 (향후 과제)

- 회원가입, 자료 공유 (`PRIVATE / SHARED / PUBLIC`)
- Knowledge Graph, Graph 검색
- GitHub·대화 기록 같은 외부 자료 자동 수집
- 사용자별 AI 프로필, 저장 용량 관리

범용 챗봇 용도는 목표가 아님.
